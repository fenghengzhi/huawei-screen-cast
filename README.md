# 华为投屏

[下载最新 APK](https://github.com/fenghengzhi/huawei-screen-cast/releases/latest) · [自动构建](https://github.com/fenghengzhi/huawei-screen-cast/actions/workflows/android.yml)

个人使用的 Android 应用，将华为手机的整个屏幕通过机顶盒已有的 DLNA 服务、部分乐播接收端的兼容镜像接口或原生 Lelink 免密码接口播放，不需要给电视安装浏览器或新的接收应用，不使用乐播收费 SDK，也无需电脑中转。三个入口独立选择，均支持系统播放声音；乐播相关入口目前为实验功能。

## 已确认的目标设备

已在中国电信投屏机顶盒和 Kodi 接收端测试。测试机顶盒的 DLNA 服务声明支持 `video/MP2T` 和 `video/m3u8`；华为 NOH-AN00 真机可发现并投送屏幕。

2026-10-02 在真机 + Kodi 上验证 1.2.0：实际编码器为海思硬件 `OMX.hisi.video.encoder.avc`。旧版在静止界面 15 秒仅发送 68 帧，出帧与网络到达间隔最大约 2.4 秒，导致接收端反复缓冲。加入固定帧率 GPU 渲染后，20 秒收到 400 帧，无 TS 连续计数错误；帧时间戳间隔 P95 约 51 ms、最大约 58 ms，网络到达间隔最大约 80 ms。用户确认画面正常、loading 明显减少或消失。上述间隔不代表端到端投屏延迟。

最初系统 Miracast 入口的方案不能满足这台机顶盒，已改成应用内实时录屏直播。系统无线投屏仅保留在帮助中的备用入口。

## 使用

### DLNA 投屏

1. 手机和机顶盒连接同一 Wi-Fi，打开机顶盒已有的投屏服务。
2. 打开应用，搜索并选择目标电视、机顶盒或 Kodi。
3. 点击“开始屏幕投屏”，首次使用允许录音权限，并同意系统屏幕共享授权。默认同步手机播放声音，不采集麦克风，无需额外开关。
4. 默认“低延迟”直接提供 MPEG-TS 直播；若机顶盒不出画面，先结束投屏，再切换“兼容模式”使用 HLS。
5. 点击“结束投屏”或通知中的“停止共享”结束录屏与本地直播服务。

DLNA 默认输出 960×540、20 fps、约 1.2 Mbps 的 H.264 画面，其他参数可在“画质设置”调整。系统播放声音默认以 AAC-LC、48 kHz、立体声、128 kbps 传输，与视频共用单调时钟。Android 仅允许捕获同一用户下、允许被捕获的媒体/游戏等播放声音；通话、禁止音频捕获的应用及受保护内容可能无声，不会退回麦克风录音。权限拒绝或采集启动失败会明确提示。HTTP 读取合并多个 TS 包，单次额外等待上限 4 ms，减少 188 字节小块发送；直播队列为 512 包。GPU 按固定时钟将最新屏幕纹理提交给硬件编码器，即使画面静止也保持连续输出。播放器本身仍会缓冲，HLS 通常更慢。受保护的视频、密码输入或安全窗口可能黑屏。

可以单独分享照片、视频和音乐：选择设备后点击“选择媒体并投屏”。通过系统文件选择器读取所选文件，缓存到应用私有目录，通过随机 URL 的本地 HTTP 服务提供给电视。支持 GET、HEAD、HTTP Range、暂停、继续及结束。单个文件最大 2 GB，不转码；媒体兼容性由机顶盒决定。结束时关闭服务器、清除缓存并释放 Wi-Fi 锁。

应用通过 mDNS 发现乐联接收端，并分别提供原生免密码镜像与旧版兼容镜像入口，不会自动替代 DLNA。连接使用实际 Wi-Fi 网络绑定，避免 VPN 或蜂窝网络误选接口。

## Lelink 免密码镜像（Beta）

1.6.0-beta.5 新增独立实现的原生 Lelink FREE 分支，不使用乐播 SDK。仅当接收端明确广播 `lelinkport`、`htv=1`、`atv=0` 时显示“Lelink 免密码镜像 · 开始投屏”。**不实现需要验证码或密码的分支**；缺失、冲突或未知模式不会被当作免密码模式，也不会在失败后自动回退兼容镜像。

选择该入口后，允许系统录屏与播放声音捕获权限。应用会在授权后再次核验接收端当前模式，完成原生免密码密钥握手，协商音视频端口，并按已保存的 H.264 / H.265、分辨率、帧率和码率发送画面。系统声音默认开启，不录制麦克风。横竖屏切换和结束投屏沿用已有的录屏生命周期；原来的“乐播兼容镜像”按钮继续保留。

免密码并不等于免握手或免接收端限制。此分支使用 `/lelink-player-info`、`/lelink-setup`、`/lelink-verify` 和加密 `SETUP`，视频走协商出的原生 TCP 通道，不走旧版 `/stream.xml`、`POST /stream` 或固定镜像端口。它只覆盖已实现的局域网镜像子集，不代表完整 Lelink SDK、云投屏、遥控或所有接收端版本。接收端的会员、时长和授权策略仍然有效，不自动重连重置计时。

原生握手、报文边界、控制与媒体格式、验证记录见[原生 Lelink 记录](docs/lelink-native.md)。虽然协议包含加密，它的旧式密钥流构造及无带外身份验证仍有安全局限，只适合可信局域网，不应传送敏感内容。

2026-10-03 已在华为 NOH-AN00 与“投屏电视M2”（原 G2/H2，接收端 8.20.56）验证原生 H.265 画面和系统声音：1080p 档、60 fps 目标、3 Mbps，海思硬件编码；截图确认实际画面，用户确认有声音。打开抖音时用户听到少量短暂爆音，随后恢复正常；同期接收端诊断帧率一度约 34–49 fps，随后回到约 58 fps，音频发送端未记录队列丢弃。尚不能据此确定发送端负载、网络或接收端缓冲中的哪一环导致爆音。原生 H.264 已有单元测试，尚未完成真机播放验证。发送会话约 5 分 42 秒后手动结束，服务及接收端音视频资源释放；这不证明接收端在五分钟限制后仍持续显示或播放。最新正常停止的加密 `TEARDOWN` 补充已通过单元测试，尚未在真机复测。377 项单元测试、Lint 和 4 项发布打包测试通过；小时级稳定性、其他接收端及端到端音画延迟仍待验证。

## 乐播兼容镜像（Beta）

这条通道使用部分乐播接收端提供的旧版 AirPlay 兼容接口，不等于完整的 Lelink 私有协议实现，也没有引入乐播 SDK。应用解析 `_leboremote._tcp` 广播，点击兼容镜像入口后先在本地检查广播的镜像端口，并请求系统录屏授权。授权前不向接收端控制或镜像端口发送 RTSP OPTIONS、GET `/stream.xml` 等主动探测，不采集或发送屏幕画面。广播名称、UID 或端口存在均不被当成投屏成功，实际能力在授权后的正式连接中校验。

1. 在“画质设置”保存分辨率、帧率、码率及 H.264 / H.265 编码格式。
2. 搜索设备，点击目标设备下的“乐播兼容镜像 · 开始投屏”入口。
3. 确认兼容镜像说明及本次画质，允许录音权限和系统录屏授权。声音默认开启，不采集麦克风；没有广播匹配音频能力的设备会明确提示仅画面。
4. 在应用中结束投屏，或使用通知中的“停止投屏”结束共享。

应用不再设置 30 秒测试截止时间，持续投屏直到用户停止、系统撤销录屏授权或连接异常。Wi-Fi 断开、对端关闭连接、网络发送失败，以及编码器连续 15 秒不产生画面时会结束共享并释放资源，不会自动重连重置接收端的计时。

兼容镜像沿用已保存的分辨率档位、帧率、码率和 H.264 / H.265 编码选择，默认 H.264，不会静默更换编码。H.265 为实验支持，需要手机硬件编码器和接收端的旧式 PC 镜像入口共同支持；无法播放时应结束投屏，再手动改回 H.264。编码尺寸按手机实际长宽比和所选编码器的对齐要求计算，不再把竖屏内容嵌入固定横屏编码画布。横竖屏变化时，应用在同一网络连接内调整编码尺寸并重新发送参数集与关键帧，不重新发起投屏会话；H.264 和 H.265 均已在 G2 验证竖屏→横屏→竖屏，其他接收端仍需测试。竖屏内容在横屏电视上仍可能有侧边留白，最终显示比例由接收端共同决定。

获得系统录屏授权后，正式客户端在同一 TCP 连接上先 GET `/stream.xml` 校验能力，再 POST `/stream`，不再提前建立并关闭另一条能力探测连接。H.264 仅画面握手保留二进制 plist；带声音或 H.265 的传统 PC 兼容配置使用无请求体的 POST，避免 G2 把分片到达的 plist 误当作视频包。随后使用 128 字节包头、编码参数集、长度前缀视频帧、心跳与 NTP 应答。H.265 通过接收端兼容的 NAL 数组容器传送 VPS/SPS/PPS，不是通用 AirPlay hvcC 封包；参数集展开后的总长度不得超过 128 字节，超出会明确提示切换 H.264 并停止。带声音时通过 RTSP/RAOP 独立传输 AAC-ELD；音视频声明一致的兼容协议类别和本应用随机生成的设备标识，防止接收端把声音误当成另一场投屏而关闭。**此配置无加密**，仅用于可信局域网，不应投送敏感内容。遇到授权拒绝或不支持的响应会停止，不提交乐播凭据、不在认证失败后切换协议重试。发送帧数只代表写入连接，不证明电视已显示画面。分析和实现边界见[互操作记录](docs/compatibility-findings.md)。

### 已验证与限制

- 2026-10-02：电信机顶盒的 RTSP OPTIONS 和 `/stream.xml` 均返回 200，但未确认其兼容镜像实际画面。后续按用户指定改用“投屏电视G2”（接收端 8.20.56），已通过接收端截图确认显示华为手机画面，硬件解码日志连续约 20 fps。
- 2026-10-03：华为真机向 G2 以 `20 fps / 3 Mbps` 连续投屏 3 分 6 秒后手动停止；同连接完成 `928×1920 → 1920×928 → 928×1920` 切换。两个方向均有接收端实际画面截图，接收端在原会话内重配硬件解码器，诊断出帧约 20 fps、队列大多数采样为 0。手动停止后编码器、前台服务及电源锁均释放。小时级稳定性、多机型兼容性和兼容镜像音频尚未验证。
- 2026-10-03（1.6.0-beta.2）：已修正授权前闪屏的连接时序缺陷。旧流程在系统录屏授权前单独请求 `/stream.xml` 后断开；G2 会因此短暂进入镜像界面再退出，即使没有收到任何屏幕帧。现已移除这次提前探测，正式连接所需的同连接 GET→POST 保留在授权之后。真机验证等待授权及点击“禁止”期间，G2 无新的镜像请求或启动记录，手机无投屏服务；随后授权后的正式连接只有一次 GET→POST，接收端持续解码约 20 fps。
- G2 需要同连接 GET→POST；直接 POST 不触发播放。填写帧头偏移 56/60 的输出尺寸反而使该接收端无法解码，当前保留这些未协商字段为零。接收端没有请求 NTP，不能据此认定 NTP 互操作已通过。
- 同日验证 G2 主动退出接收后，发送端能自动结束共享并释放前台服务及电源锁；Activity 横竖屏重建保留已发现的设备。Android 14 单应用捕获回调和实际 Wi-Fi 中断尚未在真机验证。
- **G2 明确显示“限时体验 5 分钟，开通会员享不限时投屏”。取消应用自己的 30 秒测试截止，不会取消接收端的收费或限时策略。应用不提供自动重连重置试用时间等绕过功能。**
- 2026-10-03（1.6.0-beta.3 开发版）：通过对 G2 接收端的本地互操作分析，修正了声音与画面的协议分类冲突，以及 POST 请求体分片引起的启动黑屏。初次音视频连续测试 4 分 30 秒有爆音；修复时钟抖动误丢有效 AAC 帧后再次真机测试，用户确认“声音正常，爆音消失”。第二轮持续两分多钟、约 20 fps，音频发送丢弃计数为零，同连接完成竖屏→横屏→竖屏，音频时钟应答持续正常，手动停止后声音、画面及前台服务均结束。小时级稳定性、其他机型和端到端音画延迟仍未量化验证。
- 2026-10-03（1.6.0-beta.4）：新增兼容镜像 H.265。首次 20 fps 测试确认 G2 识别 HEVC 参数集及 IDR 19，但随后被接收端会员提示暂停。用户恢复接收端后，在同一设备（已更名“投屏电视H2”）完成约 3 分 6 秒连续测试：华为海思 `OMX.hisi.video.encoder.hevc` 硬件编码，1080p 档、60 fps 目标、3 Mbps，接收端使用 `c2.qti.hevc.decoder`，稳定阶段诊断出帧约 55–59 fps、队列采样为 0。同会话完成 `928×1920 → 1920×928 → 928×1920`，截图确认实际画面持续更新；用户确认“画面、声音都正常，没有爆音”。音频发送端诊断丢弃为零，手动停止后音视频、前台服务及电源锁释放。181 项单元测试及 Lint 通过。接收端五分钟体验提示仍存在；小时级稳定性、其他接收端及端到端音画延迟仍未量化验证。
- 以上兼容路线不是原生 Lelink；beta.5 的原生 FREE 握手与媒体通道为独立入口，仍不代表完整 Lelink SDK。实验分支的普通推送只触发构建，不发布正式 Release。

兼容音频仅对广播明确声明无密码、无加密、UDP、AAC-ELD、16-bit 立体声和 44.1/48 kHz 的接收端启用。Android 系统播放捕获后由 FDK-AAC 编码为每声道 480 采样点的原始 AAC-ELD 帧；本机系统编码器只能产生的 512 采样点模式不能替代它。声音和画面共用单调时钟，包含受限队列、重传和时钟应答；连接或采集失败会停止共享，不静默伪装为声音正常。音频不会回退到麦克风，Android 禁止捕获的应用仍可能无声。现有 DLNA 的 AAC-LC 音轨不能直接复用到这条通道。[RAOP 能力字段](https://openairplay.github.io/airplay-spec/service_discovery.html)、[音频协商](https://openairplay.github.io/airplay-spec/audio/rtsp_requests/announce.html)。

公开协议事实来源：[乐播发现字段](https://github.com/lebosdk/Lebo-mDNS-Client)、[旧版镜像握手](https://github.com/openairplay/airplay-spec/blob/master/src/screen_mirroring/http_requests.md)、[封包](https://github.com/openairplay/airplay-spec/blob/master/src/screen_mirroring/stream_packets.md)、[时钟同步](https://github.com/openairplay/airplay-spec/blob/master/src/screen_mirroring/time_synchronization.md)。未复制这些项目的代码。

## 构建与测试

1.5.0 默认采集系统播放声音，使用 AudioPlaybackCapture + AudioRecord + AAC 编码，与 H.264 / H.265 视频复用到 MPEG-TS 或 HLS；停止投屏时同步释放音频采集和编码器。

Android 可能将所需录音权限显示为“访问麦克风”，但应用仅创建播放捕获配置，不连接麦克风音源。真机 H.265 + AAC 的 15 秒采样得到 299 个视频帧、699 个音频帧，TS 连续计数无中断；HLS 分片也包含视频和音频两条轨道。统计不代表接收端实际听感或端到端同步效果。

1.4.0 在“画质设置”新增 H.264 / AVC 与 H.265 / HEVC。默认 H.264，历史配置自动沿用；编码选择与分辨率等设置一并保存，并于下次投屏生效。H.265 使用 `video/hevc` 硬件编码器、MPEG-TS HEVC 流类型和 VPS/SPS/PPS 参数集。不支持相应硬件编码器时会明确报错，不会静默改成其他编码。接收端需支持所选编码在 MPEG-TS / HLS 中的播放，兼容性不佳时可切回 H.264。

1.3.0 新增“画质设置”：分辨率可选 360p / 540p / 720p / 1080p，帧率可选 15 / 20 / 25 / 30 / 60 fps，码率为 0.5–12 Mbps、步进 0.1 Mbps。设置保存到手机本地，下次开始投屏时应用；取消不修改已有设置，恢复默认后点击保存即可回到 540p / 20 fps / 1.2 Mbps。硬件不支持的编码组合会显示启动错误，不保证每台手机都能达到所有组合。GPU 固定帧率调度保留了 30 / 60 fps 的小数毫秒间隔，避免整数除法造成时钟偏差。

需要 JDK 17+、Android SDK 36、NDK 28.2.13676358 和 CMake 3.22.1：

```sh
cd android
ANDROID_HOME=/path/to/Android/sdk ./gradlew :app:assembleDebug :app:testDebugUnitTest
```

输出 `android/app/build/outputs/apk/debug/app-debug.apk`。支持 Android 10+、EMUI 和兼容安卓应用的 HarmonyOS，不支持 HarmonyOS NEXT 原生应用。

GitHub Actions 会在推送 `main`、`codex/lelink-experiment` 或向 `main` 提交 Pull Request 时自动运行构建、测试与 Lint，并上传调试 APK 供下载。普通分支推送不发布 Release；推送匹配应用版本的 `v*` 标签后，自动构建带固定发布签名的 APK 并上传到 GitHub Releases，附带 SHA-256 校验文件和第三方许可声明。签名密钥保存在仓库 Secrets 中，不进入源代码。具体流程见 [发布说明](docs/releasing.md)。

首次从本地调试版切换到 Release 版时，由于签名证书不同，需要卸载调试版再安装，原画质设置会被清除。之后的 Release 版本可直接覆盖更新。

测试涵盖 SSDP 解析、UPnP 设备描述与 URLBase、XML 实体拒绝、DIDL-Lite 转义、HTTP 字节范围、实际媒体 GET/HEAD/206/416、HLS 序列和分片过期，以及 MPEG-TS 包长、连续计数器、PAT/PMT CRC、时间戳和 PCR。

## 实现

`MediaProjection → VirtualDisplay → SurfaceTexture → EGL 固定帧率渲染 → MediaCodec H.264/H.265 → MPEG-TS → 本地 HTTP / HLS → DLNA AVTransport → 接收端播放器`。

乐播兼容镜像另走 `MediaProjection → GPU 渲染 → MediaCodec H.264/H.265 → 旧版接收端兼容封包 → TCP → 接收端镜像解码器`，不经过 MPEG-TS、HLS 或 DLNA 播放器。其声音单独走 `AudioPlaybackCapture → AudioRecord → FDK AAC-ELD → RTP/UDP → 接收端音频播放器`。

可使用 `node tools/inspect-stream.mjs <当前直播 URL> 20` 检查 TS 连续性、出帧时间戳与网络到达间隔。工具仅输出统计，不保存屏幕内容；新增直播连接会请求下一个关键帧。

录屏使用 mediaProjection 前台服务并显示持续通知；注册系统停止回调；编码线程与网络请求不运行在 UI 线程；直播队列和 HLS 分片数量有内存上限；缓冲溢出时等待下一关键帧恢复；结束时释放录屏、编码器、Surface、服务器和 Wi-Fi 锁。机顶盒 45 秒内不取流会自动停止屏幕共享。播放状态来自机顶盒返回值，不使用模拟设备和虚假连接状态。
