# G2 兼容镜像互操作记录

本记录针对 G2 接收端 8.20.56 的本地验证，不代表完整 Lelink 私有协议，也不保证其他版本具有相同行为。

## 会话分类

单独使用默认旧版 HTTP 镜像和传统 RAOP 音频时，接收端分别将其归入内部协议类别 1 和 2。其播放器调度器会保留同一来源地址、同一协议类别下的音频和视频，却会终止不同协议类别的旧会话。因此，只让两条连接使用相同的设备标识或 plist sessionID 不够。

已验证的配套配置：

- HTTP GET `/stream.xml` 与 POST `/stream` 使用 `AirParrot/1.1 HuaweiCast/1.0` 兼容格式声明。该接收端明确把此配置作为不加密的传统 PC 镜像处理，视频封包仍为 128 字节包头、avcC 和 AVCC。
- RTSP 使用本应用临时生成的 `X-LeLink-Device-ID`，不同时添加会覆盖协议分类的 `X-Apple-Device-ID`。
- 两条媒体通道均归入接收端内部类别 3，接收端保留声音播放器和画面播放器。接收端内部的音视频 sessionID 可以不同。
- H.264 仅画面模式保留原来的独立兼容路径，不要求 RAOP 成功。H.265 仅画面也使用 PC 兼容配置，但不会因此主动开启 RAOP。

G2 的传统 PC 兼容入口还存在 HTTP 分帧缺陷：匹配 POST 请求头后立即进入视频解析，没有等待 Content-Length 指定的 plist；后到达的 `bpli` 会被误读为超大视频帧长度。该入口并不需要 POST 请求体，因此带声音或 H.265 的配套配置发送完整的短请求头及 `Content-Length: 0`，再稍后开始媒体数据。H.264 仅画面路径仍发送 plist，并将请求头与请求体合并写入。这是针对已验证兼容入口的处理，不是通用 AirPlay 握手规则。

## H.265 兼容格式

G2 的旧入口不直接解析标准 hvcC；其 type-1 配置解析器接受 NAL 数组并交给支持 HEVC 的下游解码器。应用用两个序列参数数组元素携带 VPS、SPS，用一个图像参数数组元素携带 PPS，保留包头中的真实尺寸。下游识别 HEVC 参数集并选择 `video/hevc`。该容器是接收端兼容格式，不应描述成标准 AVC 配置或通用 AirPlay HEVC。

接收端的配置缓冲区只有 128 字节，发送前严格校验 `VPS.length + SPS.length + PPS.length + 12 <= 128`，每条 NAL 必须具有对应的 HEVC 类型、合法头部及独立边界。超过限制会停止，不尝试发送。配置和后续关键帧分包，并使用相同时间戳；旋转重建时清除旧代参数和队列，等待新关键帧。

旧视频解析器会按 H.264 规则移除首个看起来像 SEI 的 NAL，这会误删 HEVC IDR 19。应用在 HEVC access unit 前放置合法 AUD（已有首 AUD 则不重复），让旧解析器移除 AUD 而保留真实画面数据。H.264 路径未改变。目前实际确认的是 Huawei HEVC Main、IDR 19；其他编码器的 CRA 等随机访问形式尚未验证。

这些字段是媒体互操作配置，不代表本应用来自 AirParrot 或乐播。应用没有使用其 SDK、凭据或密钥，没有修改接收端，也没有把提取的 APK、原生库或反编译代码加入项目。分析材料只在被 Git 忽略的本地测试目录中。

## 音频格式

G2 的传统 AAC-ELD 解码路径需要每声道 480 个采样点，不接受用 512 点编码后只改 SDP 声明。44.1 kHz 的实际 ASC 为 `f8e85000`，48 kHz 为 `f8e65000`。应用使用 FDK-AAC 实际产生该格式，不复用 DLNA 的 AAC-LC 数据。

音频 RTP 包在 12 字节标准头之后直接放原始 AAC-ELD AU，没有 ADTS 或 AAC-hbr 的 AU-header。SETUP/audio 包含 `Audio-Type: sample_rate=<rate>;channels=2`，采样率必须与编码器一致。

硬件 AudioTimestamp 可能抖动、回退或暂时不可用。不能据其瞬时时间差把完整 AAC AU 判为重复帧。应用按实际输出样本数推进 RTP 时间戳，并缓慢校准到音视频共用的单调时钟；真实的队列丢弃另行计数。

## 验证与边界

2026-10-03：华为 NOH-AN00 向 G2 连续投送 4 分 30 秒，画面约 20 fps；用户确认接收端有画面和测试音。首次测试存在爆音，随后修复时间戳抖动误丢音频帧及 POST 分帧问题。第二轮用户确认“声音正常，爆音消失”，持续 3 分 8 秒后手动停止；两分多钟内发送端的诊断采样报告音频队列、过期和非法帧丢弃均为零，音频时钟应答超过 70 次，同连接完成竖屏→横屏→竖屏。接收端持续解码约 20 fps，停止时统计视频输入和输出均为 3746 帧、丢弃 0 帧，音频播放器和画面连接共同释放。

最终验证通过 168 项 Android JVM 单元测试、4 项发布打包测试及 Android Lint。听感确认只代表本次 G2 测试，不代表端到端延迟已经量化、任意网络都无爆音或其他接收端均已验证。

开始任何采集和镜像/音频握手前仍需系统录屏授权；默认只采集允许捕获的系统播放声音，不读取麦克风。接收端要求配对、密码或其他授权时停止，不在拒绝后自动更换协议重试。G2 的五分钟体验和会员提示保持原样；没有自动重连重置计时。

1.6.0-beta.4 的 H.265 验证通过 181 项单元测试与 Lint。首次真机 `928×1920 / 20 fps / 3 Mbps` 发送，G2 实际创建 `c2.qti.hevc.decoder`，识别 HEVC 参数集和 IDR 19，出帧日志约 20 fps；随后接收端显示会员限制并暂停画面、关闭连接。

用户恢复接收端正常功能后，在同一设备（显示名已改为“投屏电视H2”，接收端版本仍为 8.20.56）继续测试。华为真机使用 `OMX.hisi.video.encoder.hevc` 硬件编码，以 1080p 档、60 fps 目标、3 Mbps 连续运行约 3 分 6 秒后手动停止。接收端使用 `c2.qti.hevc.decoder`；稳定阶段诊断出帧约 55–59 fps，队列采样为 0。原会话内完成 `928×1920 → 1920×928 → 928×1920`，接收端按新尺寸重配 HEVC 解码器，截图确认三个阶段及停止前的实际画面持续更新。音频包数和会话时长连续累计，最后一组音频诊断为 offered=16580、sent=16580、各项丢弃=0、timing=94；用户听取 15 秒间歇测试音后确认“画面、声音都正常，没有爆音”。手动停止后音视频连接、接收端 AudioTrack、手机前台服务及电源锁均释放，并恢复手机原有自动旋转设置。

本轮验证不代表小时级稳定性、任意接收端兼容性或已量化的端到端音画同步。接收端仍显示五分钟体验提示；应用没有为恢复测试而重置接收端、自动重连或规避限制。

传输没有加密，只适合可信局域网。当前不包含完整 Lelink 私有会话、收费功能解锁或通用跨接收端兼容承诺。
